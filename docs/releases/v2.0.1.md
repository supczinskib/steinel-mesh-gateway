# Steinel Mesh Gateway v2.0.1

Version 2.0.1 improves command scheduling, device-state reporting and web diagnostics across supported Mesh devices.

### Changes

- Send switching, brightness, automatic-control and light-control property commands without waiting for acknowledgements, so an unanswered write does not hold up following commands. Use one bounded repetition and separate reads to verify device state.
- Prioritize new commands and discard superseded repetitions. Finish pending repetitions before slow readbacks while preserving time for background polling.
- Refresh output states independently of discovery and stale optional values. Adapt polling to network workload, bound read timeouts and retry missing replies separately for each output.
- Use the current Lightness value to update On/Off when both describe the same dimmable output, and alternate read methods after repeated missing On/Off replies. Keep twilight-sensor controls unchanged.
- Report device-confirmed **Output** state in Home Assistant. A queued command no longer changes this state before confirmation, preventing incorrect automation conditions. Keep immediate pending settings in the web interface and preserve entity identities.
- Update selected-device states from diagnostic replies and unsolicited publications. Accept late replies without completing unrelated requests and resume polling when authenticated state updates show that a device is responding again.
- Prioritize due output reads over diagnostic probes and keep report collection progressing when optional properties do not reply.
- Add **Command trace** to the web diagnostics: manually started passive capture for all devices, up to three minutes, JSON download and missing-event indicators. The gateway uses a fixed buffer of at most 2 KiB; the browser stores the history. Capture sends no additional Mesh requests.
- Recognize the L 840 SC (`0x1e7e`) and L 840 C (`0x1eba`) product identifiers while retaining existing device names.
- Allow manually installed release candidates to update to the matching stable release through the built-in updater, without offering an older stable version.
- Update all README translations and expand regression coverage for command ordering, missing replies, diagnostics and Home Assistant state handling.

Physical lamp activation delays remain under investigation. Their cause has not been isolated, and this release does not resolve all reported delays. State reporting still partly depends on polling and device replies.
